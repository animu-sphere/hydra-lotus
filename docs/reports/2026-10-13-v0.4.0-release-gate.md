## Gate observations

- Both physical-GPU configurations enabled synchronization validation and
  reported no validation messages.
- The deterministic Cornell reference checks, BSDF/MIS transport and
  analytic/environment lighting oracles passed under both integrators.
  Committed reference images were not regenerated.
- Temporal CPU lifecycle and independent projection tests, GPU surface
  history, reprojection/validity and bounded radiance tests passed under
  both integrators. Their independent oracles, disjoint sample batches,
  static equivalence, moving sequences, rejection codes, reset policy and
  failed-call recovery are described in the linked
  [scope evidence](2026-10-13-temporal-hydra-exit.md#renderer-phase-4-scope-review).
- Hydra controls and debug AOVs passed synthetic and composed moving-stage
  tests. Installed usdview verified static accumulation, camera/object
  motion, explicit cuts and return to progressive rendering, with retained
  renderer/targets and no synchronization messages.
- The latest implementation's hosted
  [renderer CI](https://github.com/animu-sphere/hydra-lotus/actions/runs/38272964482)
  passed documentation, runtime-free core and digest-pinned Hydra jobs for
  `2436626`. Hosted capability SKIPs remain separate from physical evidence.
- The viewport retains its accepted
  [foundation disposition](2026-10-10-foundation-closure.md); it was not
  rerun for this release.

## Repeatable package

Two `ost package --profile lookdev --intent hydra --json` invocations
returned the same archive digest:

```text
sha256:04071769149192701e0f3af534207b7a9cd0dec8dc962027f235c823f9da2c33
```

The 2,654,898-byte archive has 34 manifest entries, including the temporal
public header, required shaders beside the headless runner and Hydra
plugin, reference images and licensed Stinson Beach validation assets.
`scripts/release.py stage` verified package identity, digest agreement,
actual archive hash, SBOM identity and required products. The local bundle
is assembled under `build/release-v0.4.0-bundle`, including source,
checksums and notes through `scripts/release.py bundle`. Tag-driven Actions
rebuild the published package on the hosted runner.
