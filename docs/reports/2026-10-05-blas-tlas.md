# BLAS and TLAS in the GPU scene

Measured on 2026-10-05 in `hydra-lotus`, on the working tree based on
`30ed317`, Windows 11 x86_64, MSVC 14.51, OpenStrata 0.23.14, Release,
Vulkan SDK 1.3.290 headers. The GPU was an NVIDIA RTX A5000 (Vulkan device
API 1.4.329, loader API 1.4.321). Hydra used the installed OpenUSD 26.08
lookdev runtime and CPython 3.13. These are local checks; no hosted CI run
was measured.

## Scope

This is the third step of the Renderer Phase 1 vertical slice: the GPU
scene builds a BLAS per resident geometry and a TLAS over its instances
([scene reference](../reference/SCENE.md#acceleration-structures)). No pass
traces them yet. The bootstrap triangle is still what is drawn, so no image
in this run is evidence that an acceleration structure is correct. What is
checked is the TLAS build input, the build and update counts, and Vulkan
validation. Ray queries and BLAS refit or compaction are not part of it.

All checks are exact comparisons on synthetic scenes. Sample count and RNG
seed do not apply.

## Fixtures

`renderer.scene.acceleration`, written by `lotus-headless`, follows the
same walk as `renderer.scene.upload`: a quad, a triangle and a mesh without
triangles go through insertion, an unchanged commit, a transform edit, a
hide, a point edit and removal. After each step it reads back the TLAS
build input and compares every instance with its instance record: the same
order, a BLAS reference that resolves to the record's geometry slot, mask
`0xFF`, and the first three rows of the record's transform. It also
checks the counters:

| Step | BLAS builds | TLAS builds | TLAS updates |
| --- | --- | --- | --- |
| insertion | 2 | 1 | 0 |
| unchanged commit | 2 | 1 | 0 |
| transform edit | 2 | 1 | 1 |
| hide | 2 | 2 | 1 |
| point edit | 3 | 3 | 1 |
| removal | 3 | 4 | 1 |

and that the BLAS and TLAS instance counts equal the resident geometry and
instance counts after every step. The check runs before the 1,000 bootstrap
frames, so `renderer.validation.messages` covers the builds too.

Two deliberate faults were each reverted before the runs below:

- writing the TLAS transform from the matrix's columns instead of its rows
  made the check fail with "insertion: the TLAS build input differs from
  the instances";
- never refitting the TLAS made it fail with "transform edit: expected a
  TLAS update and no build".

`lotus-renderer-hydra-aov` now also checks, when the device has
acceleration structures, one BLAS and one TLAS instance for the triangle,
a second BLAS and TLAS build after the topology change to a quad, and no
TLAS instance and no new BLAS once the mesh is hidden. The usdview smoke
test reads the same counts from its evidence log; on this machine every
frame reported `acceleration=1`, one BLAS and one TLAS instance, and the
point edit built exactly one more BLAS.

## Verification

Before the builds, objects with no recorded header dependencies were
deleted, the known Japanese-MSVC workaround
([roadmap](../roadmap/current.md#project-infrastructure)): 8 in the
runtime-free tree and 9 in the Hydra tree.

- `ost build --jobs auto`, `ost test`: **8/8 passed**. `ost validate`:
  **passed**, `renderer.scene.acceleration` OK, Hydra checks skipped by
  configuration.
- `ost build --without-runtime --intent ci-core`,
  `ost test --without-runtime --intent ci-core`: **8/8 passed**;
  `renderer.scene.upload` and `renderer.scene.acceleration` are explained
  SKIPs ("Vulkan backend was not compiled for this configuration").
- `ost build --profile lookdev --intent hydra`,
  `ost test --profile lookdev --intent hydra`: **14/14 passed**, including
  the AOV integration and usdview host tests.
- `ost validate --profile lookdev --intent hydra --strict-renderer-evidence`:
  **passed**; every renderer assertion including
  `renderer.scene.acceleration` OK, zero Vulkan validation messages. The
  viewport and artifact-integrity checks were SKIP because this run
  launched no viewport and packaged no artifact.
- `ost renderer viewport -- --frames 8 --hidden`: presented 8 frames;
  `ost validate --intent renderer-viewport`: **passed**, including
  `renderer.scene.acceleration` and `renderer-viewport`.

The device-without-acceleration-structures path, where
`renderer.scene.acceleration` is a SKIP naming the missing extension or
feature, was not exercised: this machine has one GPU and it supports them.
Synchronization validation was not enabled
([roadmap](../roadmap/current.md#testing-infrastructure)).

The current API and its limits are in the
[scene reference](../reference/SCENE.md#acceleration-structures); remaining
work is in the
[roadmap](../roadmap/current.md#renderer-phase-1--reference-path-tracer).
