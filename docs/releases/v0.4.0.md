# v0.4.0 — Temporal infrastructure release

Released on 2026-10-13 under Apache-2.0. This release adds Renderer Phase 4:
CPU/GPU frame history, rigid motion, backward reprojection, shared history
validity and opt-in bounded temporal radiance accumulation. Both reference
and wavefront integrators support it, headless and through Hydra.
Deterministic progressive rendering remains the default.

## Shipped capabilities

- `lotus/temporal.hpp` exposes immutable current/previous frame snapshots,
  compatibility and reset policy, stable rigid-placement correspondence,
  backward pixel motion and shared depth/normal/identity/motion validity.
  The CPU foundation is available with Vulkan disabled.
- `OffscreenRenderer::RenderTemporalScene` produces pixel-centre primary
  depth, geometric normals and identities, retains previous GPU surfaces,
  and computes backward reprojection and validity under both integrators.
  History advances only after a successful frame.
- Optional radiance accumulation traces disjoint fresh sample batches and
  blends accepted per-pixel history with a bounded effective sample count.
  Camera and rigid motion reuse compatible history; scene, lighting and
  render-setting changes reset it automatically.
- Hydra settings `lotus:temporal`, `lotus:historySamples`, `lotus:historyKey`
  and `lotus:historyReset` select accumulation, cap history, declare
  compatibility changes and request one-shot cuts. Temporal passes remain
  unconverged so hosts continue drawing fresh batches.
- Hydra motion, history-length, validity and rejection AOVs expose the
  history decisions. Metadata-only debug rendering retains progressive
  convergence. Primary-surface, reprojection and accumulation GPU passes
  each have separate timestamps and retain their buffers at fixed extents.
- Community guidelines, security reporting instructions and GitHub issue
  and pull-request templates accompany the release.

Detailed changes are in the [changelog](../../CHANGELOG.md#040---2026-10-13).
The [temporal contract](../reference/TEMPORAL.md) owns API behavior, controls
and limits. The [Renderer Phase 4 exit review](../reports/2026-10-13-temporal-hydra-exit.md#renderer-phase-4-scope-review)
and [release gate](../reports/2026-10-13-v0.4.0-release-gate.md) record the
scope review and verification.

## Correctness and measurement

CPU tests check frame lifecycle, stable correspondence, independent camera
projections and rejection boundaries. GPU tests compare every validity
code and fetched history index with the CPU oracle, exercise all rejection
codes, and compare radiance and history counts with independent fresh
batches under both integrators. Static accumulation matches progressive
transport within float summation precision; moving and disoccluded scenes
are compared with independent references.

Moving composed USD stages and the installed usdview host verify camera
and rigid object motion, bounded history, one-shot cuts, compatibility and
settings changes, debug AOVs and return to progressive rendering. Physical
GPU checks include synchronization validation and the existing deterministic
reference images, which were not regenerated. Evidence is recorded in the
[foundation](../reports/2026-10-12-temporal-foundation.md),
[primary-surface](../reports/2026-10-12-temporal-primary-surfaces.md),
[validity](../reports/2026-10-12-temporal-gpu-validity.md),
[radiance](../reports/2026-10-12-temporal-radiance.md) and
[Hydra](../reports/2026-10-13-temporal-hydra-exit.md) reports.

## Compatibility and delivery

The `v0.4.0` tag publishes the Windows x86_64 CY2026 lookdev/Hydra package
`lotus-0.4.0-cy2026-windows-x86_64-py313-lookdev--hydra.tar.zst`, its manifest
and SPDX SBOM, `hydra-lotus-0.4.0-src.tar.gz` and `SHA256SUMS` through the
[release workflow](../guides/RELEASING.md). The package requires matching
OpenUSD 26.08/Python 3.13 and Vulkan runtimes. Other configurations build
from source with the [building guide](../guides/BUILDING.md).

Measured configuration: Windows 11 x86_64, MSVC 14.51, OpenStrata 0.23.14,
NVIDIA RTX A5000 and OpenUSD 26.08/Python 3.13 for Hydra. GPU requirements
remain in the [configuration reference](../reference/SUPPORTED_CONFIGURATIONS.md#requirements).

Public API additions include temporal frame/history/settings and debug
records, `RenderTemporalScene` and temporal evidence. Existing callers of
`RenderScene` retain progressive behavior. Hydra temporal accumulation is
disabled by default; enabling it requires colour clears and ray queries.
`max_samples` caps each fresh batch in radiance mode, while retained history
is controlled separately by `max_history_samples`.

## Known limitations at release

- Reprojection fetches the nearest previous pixel. There is no history
  filtering, radiance neighbourhood clamp, anti-lag heuristic or BRDF
  correction; view-dependent shading, indirect lighting and silhouettes
  can lag or ghost during motion. Moving illumination reuse is approximate.
- Correspondence supports rigid motion. Geometry deformation is rejected;
  same-count instance reordering requires an explicit cut or compatibility
  key change. There is no automatic camera-cut heuristic.
- Each Hydra delegate retains one GPU view. Switching render passes cuts
  history; concurrent per-view history is unavailable. Metadata uses fixed
  pixel-centre coverage while radiance retains jittered box filtering.
- ReSTIR, reservoir state, denoising and spectral rendering remain outside
  this snapshot. Production material expansion and light acceleration
  retain their later phase assignments.
- The viewport still presents the bootstrap triangle, readback is blocking,
  Hydra ID channels remain CPU sentinels, and material translation is the
  minimal subset. Linux, macOS and AMD/Intel GPUs have not been measured.

Precise constraints stay with the [temporal contract](../reference/TEMPORAL.md),
[configuration limitations](../reference/SUPPORTED_CONFIGURATIONS.md#foundation-bootstrap-limitations),
[scene/material reference](../reference/SCENE.md) and
[AOV contract](../reference/AOVS.md). Future work lives in the
[active roadmap](../roadmap/current.md).
