# v0.5.2 — Viewport foundation release

Released on 2026-10-18 under Apache-2.0. This patch release ships the
standalone viewport's foundation, step 2 of the
[v0.6.0 plan](../roadmap/README.md#v060--interactive-rendering), ahead of the
denoiser: `lotus-viewport` becomes the renderer's frontend for everyday use,
presenting progressive path tracing from the backend and letting a developer
watch and switch the renderer's modes while it runs. Rendering defaults,
Hydra settings and AOVs are unchanged from [v0.5.1](v0.5.1.md). Ongoing scope
and release targets remain in the
[canonical roadmap](../roadmap/README.md#status-at-a-glance).

## Shipped capabilities

- **Presentation.** The viewport presents the latest scene frame from the
  backend into an sRGB swapchain, without a CPU readback: the reference
  Cornell box by default, or a USD stage through the Hydra adapter driven in
  process (`viewport-usd` intent). Resize, fullscreen, scripted runs with
  validation, explained skips and benchmark JSON
  ([evidence](../reports/2026-10-17-viewport-presentation.md)).
- **Camera and stage.** usdview's free camera (tumble, track, dolly,
  frame), the stage's authored cameras with hand-over to the free camera,
  stage time codes, layer reload and pending edits applied every frame;
  camera and scene changes restart the accumulation
  ([evidence](../reports/2026-10-17-viewport-camera.md)).
- **Run-time controls and debug views.** A Dear ImGui developer UI switches
  the reference or wavefront integrator, the sample limit and accumulation,
  NEE/MIS, ReSTIR off, initial, temporal, spatial or combined and temporal
  radiance reuse, and presents depth, normal, motion, temporal validity and
  reservoir validity, age and weight from the GPU. Presented reuse frames no
  longer read back their evidence products, about fifty times cheaper at
  128x128 ([evidence](../reports/2026-10-18-viewport-controls.md)).
- **Timing HUD.** The host frame time, each GPU pass's time, adding up to the
  frame's GPU time, the sample count, the latest scene update's upload, BLAS
  and TLAS times, and reservoir, history and scene memory
  ([evidence](../reports/2026-10-18-viewport-timing.md)).
- **Stage selection.** The Hydra-enabled viewport opens a stage from a
  native file dialog and renders it in the same window, keeping the controls.
- **Build structure.** The backend owns its shader graph behind one target,
  hosts stage shaders through one helper, warnings and the C++ standard are
  target properties, and `LOTUS_ENABLE_VULKAN=ON` fails configuration
  without the Vulkan SDK or `slangc`
  ([evidence](../reports/2026-10-17-cmake-cleanup.md)).

Detailed changes, including the API additions behind these, are in the
[changelog](../../CHANGELOG.md#052---2026-10-18); the
[release gate](../reports/2026-10-18-v0.5.2-release-gate.md) records
verification.

## Fixes

- GPU reservoirs could leave their first positive candidate unselected
  about once in 10^7 draws, which the evidence path reported as invalid
  reservoir arithmetic at 1280x720; the first positive weight is now always
  selected, as on the CPU
  ([evidence](../reports/2026-10-18-viewport-controls.md#findings-fixed-on-the-way)).
- A progressive frame after a fresh batch (temporal radiance or reservoir
  reuse) now always restarts the accumulation.

## Compatibility and delivery

The `v0.5.2` tag publishes the Windows x86_64 CY2026 lookdev/Hydra package
`lotus-0.5.2-cy2026-windows-x86_64-py313-lookdev--hydra.tar.zst`, its manifest
and SPDX SBOM, `hydra-lotus-0.5.2-src.tar.gz` and `SHA256SUMS` through the
[release workflow](../guides/RELEASING.md). The binary package requires
matching OpenUSD 26.08/Python 3.13 and Vulkan runtimes. It contains the Hydra
plugin and headless runner, not the viewport, which builds from source with
the [building guide](../guides/BUILDING.md#the-standalone-viewport) and
fetches GLFW, Dear ImGui and nativefiledialog-extended at pinned commits.

Measured configuration: Windows 11 x86_64, MSVC 14.51, OpenStrata 0.23.14,
NVIDIA RTX A5000 and OpenUSD 26.08/Python 3.13 for Hydra.

`OffscreenTarget::read_back` false now also leaves temporal and reservoir
records on the GPU; hosts that need them keep the default. `PresentSession`
and `CreatePresentSession` are removed in favour of the renderer's own
presentation (`PresentOptions`, `OffscreenRenderer::Present`). The
`lotus-renderer-shaders` target is now `lotus-shaders`.

## Known limitations at release

- The viewport intermittently loses the Vulkan device at its second frame,
  with a GPU reset in the system log, in every mode and both builds; its
  cause is not established
  ([limits](../reports/2026-10-18-viewport-timing.md#limits)).
- Reuse modes hold 1,280 bytes per pixel of reservoirs, half of it host
  mirrors a presented frame does not read (562.5 MiB at 1280x720)
  ([memory](../reports/2026-10-18-viewport-timing.md#memory)).
- There is no denoiser; temporal and spatial reuse remain noisy and
  correlated, and NEE/MIS stays the default path.
- The viewport presents linear radiance clamped to sRGB without exposure or
  tone mapping, and a picked stage restarts its accumulation with a new
  renderer.
- Linux, macOS and AMD/Intel GPUs are unmeasured.

Remaining work is in the [active roadmap](../roadmap/current.md).
