# v0.7.0 — Performance and production foundation release

Released on 2026-10-28 under Apache-2.0. This release completes the
[v0.7.0 practical-foundation milestone](../roadmap/README.md#v070--performance--production-foundation):
Lotus measures its renderer on shared workloads, explains and removes the
leading costs it found, holds less frame state, and checks its
`UsdPreviewSurface` translation against committed fixtures and reference
images. It ships selected subsets of Renderer Phases 8 and 9 under the
[cross-phase rule](../design/ROADMAP_POLICY.md#cross-phase-delivery) and
completes neither phase. Rendered images are unchanged except for rounding
in the light crossing hierarchy. Ongoing scope and release targets remain
in the [canonical roadmap](../roadmap/README.md#status-at-a-glance).

## Shipped capabilities

- **Shared performance baseline.** Versioned fixtures (Cornell box,
  textures, instances, geometry, analytic lights, environment and 256
  sphere lights) drive headless and viewport runs from one manifest, with
  warmup exclusion, raw timing populations, optional clock and power-state
  telemetry, kept failures, headless camera and object motion, a split of
  each blocking frame's host time, and quality curves against finite
  references on two fixtures
  ([baseline](../reports/2026-10-21-shared-performance-workloads.md),
  [closure](../reports/2026-10-28-practical-foundation-closure.md)).
- **The three leading costs, fixed.** Readback buffers use host-cached
  memory, removing about 1.1 ms from each 128x128 blocking frame
  ([evidence](../reports/2026-10-25-frame-host-split.md)). Rays find the
  analytic lights they cross through a hierarchy, so a 256-light frame's
  scene pass is 5.3–8.0x faster under both integrators
  ([evidence](../reports/2026-10-25-light-crossing-hierarchy.md)).
  Deformation stages only the changed sections of a mesh, 67% fewer bytes
  on the large mesh ([evidence](../reports/2026-10-25-changed-section-staging.md)).
- **Less frame state.** `OffscreenRenderer::Residency()` lists every
  allocation by owner and memory kind with the process's heap usage
  ([inventory](../reports/2026-10-26-frame-residency.md)). Host readback
  mirrors are allocated only by frames that read back, so the viewport and
  Hydra's presentation hold none: 6.83 GiB less host-visible memory at 4K
  with SVGF and both reuse passes
  ([evidence](../reports/2026-10-26-lazy-readback-mirrors.md)). Reservoir
  history stores each frame's surfaces once, 1.0 GiB less device memory at
  4K with spatial reuse and a faster spatial pass
  ([evidence](../reports/2026-10-26-reservoir-history-split.md)).
- **Material fixtures.** Five committed `UsdPreviewSurface` stages cover
  base colour and metallic/roughness, textures and UV, shading normals and
  normal maps, emission and alpha masks, each with a C++ mirror and a
  4096-spp reference. Every headless build compares both integrators with
  the references, and Hydra's extraction and images equal the mirror's
  exactly. The adapter now warns about untranslated shader connections and
  ignored `GeomSubset` material bindings instead of ignoring them silently
  ([closure](../reports/2026-10-28-material-foundation-closure.md)).

Detailed changes, including the API additions behind them, are in the
[changelog](../../CHANGELOG.md#070---2026-10-28); the
[release gate](../reports/2026-10-28-v0.7.0-release-gate.md) records
verification.

## Compatibility and delivery

The `v0.7.0` tag publishes the Windows x86_64 CY2026 lookdev/Hydra package
`lotus-0.7.0-cy2026-windows-x86_64-py313-lookdev--hydra.tar.zst`, its manifest
and SPDX SBOM, `hydra-lotus-0.7.0-src.tar.gz` and `SHA256SUMS` through the
[release workflow](../guides/RELEASING.md). The binary package requires
matching OpenUSD 26.08/Python 3.13 and Vulkan runtimes. It contains the Hydra
plugin and headless runner, whose material check reads the five fixtures'
packaged references, not the viewport, which builds from source with the
[building guide](../guides/BUILDING.md#the-standalone-viewport).

Measured configuration: Windows 11 x86_64, MSVC 14.51, OpenStrata 0.23.14,
NVIDIA RTX A5000 (driver 597.16) and OpenUSD 26.08/Python 3.13 for Hydra.

`PathTracingSettings::light_crossing` defaults to the hierarchy; `Linear`
keeps the previous loop. The private 192-byte reservoir history record
became 64-byte `RestirReusePixel` records beside a separate pair of surface
buffers; with spatial reuse the reservoirs hold 512 instead of 640 bytes per
pixel, and read-back mirrors copy records only. The
temporal and reservoir byte fields count host mirrors only once a frame has
allocated them. `GpuFrameEvidence` adds `host_timings` and `GpuSceneStats`
adds `light_hierarchy_bytes`. Cornell quality summaries use
`lotus-quality-curve-v2`. Adapter sources moved into responsibility
directories ([layout](../architecture/PROJECT_LAYOUT.md#adapter-source-organization)).

## Known limitations at release

- Timings were measured at unlocked clocks; no adopted change rests on a
  difference within the spread between processes
  ([dispositions](../reports/2026-10-28-practical-foundation-closure.md#deferred-and-accepted-items)).
- Motion is measured headless only; Hydra's dirty-bit translation and a
  viewport motion mode are unmeasured, and deforming the largest fixture
  still spends 2.1–2.4 ms per frame in a blocking update.
- Finite-reference quality curves exist for the Cornell and textured
  fixtures only.
- Residency is sampled between calls, not as a continuous peak.
- `UsdTransform2d`, per-face `GeomSubset` materials, `displayOpacity` on
  unbound meshes, mipmaps and transparent opacity are not supported; the
  adapter warns where it ignores an authored input
  ([material dispositions](../reports/2026-10-28-material-foundation-closure.md#deferred-and-accepted-items)).
- The viewport intermittently loses the Vulkan device at its second frame on
  the measured NVIDIA driver, which also left the viewport baseline without
  complete repeats; headless and Hydra offscreen rendering are unaffected
  ([limitation](../reference/SUPPORTED_CONFIGURATIONS.md#driver-limitations)).
- Linux, macOS and AMD/Intel GPUs are unmeasured.

Remaining work is in the [active roadmap](../roadmap/current.md).
