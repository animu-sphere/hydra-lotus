# v0.2.0 — Wavefront release

Released on 2026-10-11 under Apache-2.0. This release adds Renderer Phase 2:
a wavefront path tracer that reproduces the reference transport, selectable
headless, in the benchmark and through Hydra. The reference path tracer,
materials, Hydra extraction and backend shipped in [v0.1.0](v0.1.0.md) are
unchanged in behavior; the reference integrator stays the default.

## Shipped capabilities

- `PathTracingSettings::integrator` selects the reference integrator or the
  wavefront integrator. The wavefront integrator runs the reference
  transport as compute kernels — a camera kernel that traces the camera
  rays, intersect and shade rounds over per-bounce queues with indirect
  dispatches, and a tail kernel for the remaining bounces — and a resolve
  pass adds each ended path's sample to the accumulation. The transport is
  shared with the reference integrator through common Slang modules.
- Path state is stored by section, so each kernel reads and writes only
  what it uses. Rounds are recorded only for bounces whose queues held at
  least 1/16 of the camera rays in the previous sample.
- Frames report per-bounce queue occupancy, the rounds run and per-kernel
  GPU timings. `--benchmark-integrator wavefront` repeats the fixed
  workloads under the wavefront integrator, and `--benchmark-size` measures
  other square targets.
- The `lotus:wavefront` Hydra render setting, listed by usdview as the
  checkable *Wavefront integrator* item in its Hydra Settings menu, selects
  the integrator; a change restarts the accumulation. The plugin installs
  the wavefront kernels with its shaders.
- The first tag-driven release: a Windows Hydra package, its manifest and
  SPDX SBOM, a source archive and `SHA256SUMS`, assembled and published by
  the [release workflow](../guides/RELEASING.md).

## Correctness

On the measured device the wavefront integrator reproduces the committed
Cornell reference and the four fixed benchmark images bit for bit, headless
and through Hydra. Equivalence is judged by the
[reference tolerance](../reference/SCENE.md#reference-images); bitwise
agreement is recorded, not required. The committed reference images were not
regenerated for this release.

## Compatibility and delivery

The `v0.2.0` tag publishes, through GitHub Actions, the Windows x86_64
CY2026 lookdev/Hydra package
`lotus-0.2.0-cy2026-windows-x86_64-py313-lookdev--hydra.tar.zst` with its
manifest and SBOM, the source archive `hydra-lotus-0.2.0-src.tar.gz` and
`SHA256SUMS`. The package needs a matching OpenUSD 26.08/Python 3.13 runtime
and Vulkan; it does not bundle them. Other configurations build from source
with the [building guide](../guides/BUILDING.md).

Measured configuration: Windows 11 x86_64, MSVC 14.51, OpenStrata 0.23.14,
NVIDIA RTX A5000 and OpenUSD 26.08/Python 3.13 for Hydra. The wavefront
integrator additionally needs compute support on the scene passes' queue
family and the installed wavefront kernels; the other GPU requirements are
listed in the
[configuration reference](../reference/SUPPORTED_CONFIGURATIONS.md#requirements).

Public API changes since v0.1.0 are additions: `Integrator`,
`PathTracingSettings::integrator`, `kMaxWavefrontBounces`,
`RayQueryShaders::wavefront`, `WavefrontTimings`,
`GpuFrameEvidence::wavefront_path_counts`, `wavefront_rounds` and
`wavefront_timings`, and `HdLotusRenderDelegate::GetFrameEvidence`. Existing
callers keep the reference integrator.

## Known limitations at release

- The wavefront integrator is slower than the reference integrator: 1.43
  times at 1024×1024 on `cornell-v1` and 2.5–2.8 times on the 128×128
  fixed workloads. Path classification is deferred to Renderer Phase 8,
  where materials first differ in how they shade.
- Light transport still uses brute-force sampling. Explicit direct-light
  sampling/NEE/MIS, ReSTIR, temporal reconstruction, denoising and spectral
  rendering are outside this snapshot.
- The standalone viewport presents the bootstrap triangle; the offscreen
  renderer has one frame in flight and blocking CPU readback. Hydra ID
  channels are CPU sentinels, so picking is unavailable.
- Material and texture translation is the minimal Renderer Phase 1.5
  subset. Production MaterialX/OpenPBR, glass/transmission and broader
  light/scene coverage are outside this snapshot.
- Linux, macOS and AMD/Intel GPUs have not been measured, and only the
  measured Windows configuration is packaged. Japanese MSVC dependency
  discovery and OpenStrata workflow/runtime-free validation selection
  require the documented workarounds.

The precise constraints and rationales are recorded in the
[configuration limitations](../reference/SUPPORTED_CONFIGURATIONS.md#foundation-bootstrap-limitations),
[scene/material reference](../reference/SCENE.md) and
[AOV contract](../reference/AOVS.md). Future implementation work is tracked
in the [active roadmap](../roadmap/current.md).
